## Project Title
**CardioTwin AI** — Continuous Cardiovascular Risk Digital Twin with EHR + Wearable Fusion

## Problem Statement & Healthcare Use Case
Cardiovascular disease is typically caught reactively — after symptoms appear or during a scheduled checkup — rather than proactively, from the gradual physiological drift that precedes an event. CardioTwin AI builds a *digital twin* of a patient's cardiovascular state by continuously fusing:

- **Static/historical EHR data**: age, BMI, blood pressure history, cholesterol, diabetes history, smoking status, prior cardiac events, family history
- **Dynamic wearable time-series**: 14-day rolling heart-rate variability (HRV), resting heart rate, sleep duration, and step count

Rather than judging a patient from a single snapshot, the system tracks the **trajectory** of these signals against the patient's own personal baseline, flagging early, personalized deterioration — the same reasoning a clinician uses when they say "your resting heart rate has been creeping up all week."

**Important scope note (research PoC):** CardioTwin AI estimates cardiovascular risk and flags abnormal physiological trajectories. It does **not** claim to predict specific clinical events (e.g. heart attacks) — this is a research prototype built on synthetic data, not a diagnostic tool.

## Technical Stack
- **Data**: synthetic patient generation (Python, NumPy/Pandas) — no real patient data used, per DPDP Act / HIPAA sandbox rules
- **Modeling**: scikit-learn — Logistic Regression (selected), compared against Random Forest and Gradient Boosting baselines
- **Feature fusion**: EHR static features + engineered wearable trend features (baseline vs. recent averages, slopes, volatility) — this trend-based engineering is what lets a simple, interpretable linear model capture trajectory rather than a single reading
- **Explainability**: model coefficients / feature importances surfaced directly in the dashboard's "Contributing Factors" panel
- **Dashboard**: single self-contained HTML/JS page — runs the *actual trained model* (exported coefficients + scaler) client-side, no server required
- **What-if simulation**: re-scores a perturbed feature vector through the same trained model — no retraining, fully transparent

## Data Sources & Sandbox Compliance
All data is synthetic, generated by `data/generate_data.py`:
- Three underlying population archetypes (stable / emerging-risk / high-risk) drive correlated EHR + wearable generation
- Risk labels are derived from each **patient's own baseline drift** (not population thresholds), with injected label noise to avoid a trivially learnable, leakage-based task
- No datasets requiring credentialed access (e.g. MIMIC-IV) are required to run this project — everything reproduces from the generator script alone

## Model Performance
| Model | Accuracy | Macro F1 | Macro AUC |
|---|---|---|---|
| Logistic Regression (selected) | 0.91 | 0.92 | 0.96 |
| Random Forest | 0.91 | 0.92 | 0.96 |
| Gradient Boosting | 0.88 | 0.89 | 0.96 |

Logistic regression was selected as the deployed model after comparison — it performed on par with more complex alternatives while remaining fully interpretable for clinical use.

## How to Run
```bash
pip install -r requirements.txt
python data/generate_data.py          # generates synthetic dataset
python models/train_model.py          # trains + compares models
python models/export_for_dashboard.py # exports model for the dashboard
```
Then open `dashboard/cardiotwin_dashboard.html` directly in any browser — no server needed.
